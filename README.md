# Momentum｜週間自律

個人用的週間時間表與習慣追蹤。打開看「現在該做什麼」，並記錄每天的習慣、筆記與每週回顧。

核心規則：每天 23:00 就寢，不延後睡眠補進度；不補償，今天沒完成的明天不要做兩倍；休息前先決定要休息多久；同一時間只維持一個主要自主專案。完整規則見 [docs/rules.md](docs/rules.md)，還沒完成的工作記在 [docs/plan.md](docs/plan.md)，這份文件只講程式。

## 功能

- **今天**：最上方的「現在」區塊顯示目前時段、還剩多久、進度尺與接下來的時段，下方是整天的時間表。可切換查看同一週的其他天，也可以前後翻週。
- **調整時間表**：按「調整時間表」進入調整，按住左邊的上下箭頭拖曳調整先後（鍵盤用上下鍵），在原位改名稱、開始時間與類型，也能新增、刪除。只填開始時間，每個任務延續到下一個任務開始，最後一個到 23:00 就寢；確認時會依開始時間自動排好。按「更新時間表」儲存後還能再調整，連已結束的任務都能改；按「保存當天時間表」會儲存並定稿，這一天之後不能再調整。過去的日子也不能調整。調整只套用在那一天，「還原原定時間表」可以回到預設。
- **恢復模式**：每天一個勾選。勾選時把還沒完成的運動時段標示為取消，勾選前已完成的不受影響。
- **習慣追蹤**：每天打勾，旁邊即時顯示「本週完成次數 / 每週目標」。
- **每日筆記**：記錄深度工作的產出、進度與下一步。
- **本週**：每個習慣用七個方格顯示這週每天的完成狀況，另有每天的起床、上課、深度工作、運動、英文、閱讀時間。
- **回顧**：每週固定問題，自動儲存；可匯出／匯入備份。
- **網址**：`#/today`、`#/week`、`#/review`，瀏覽器的上一頁、下一頁可用。

## 快速開始

需要 Node.js 20.19 以上（或 22.12 以上），這是 Vite 8 與 Sass 的要求。

```bash
npm install
npm run dev
```

會自動開啟瀏覽器。**日常請用 `npm run dev`**，這樣紀錄才會寫入資料夾。

| 指令                     | 說明                                   |
| ------------------------ | -------------------------------------- |
| `npm run dev`            | 開發伺服器，含存檔功能                 |
| `npm run build`          | 先跑 `check`，通過後建置到 `dist/`     |
| `npm run preview`        | 預覽建置結果（同樣含存檔功能）         |
| `npm run check`          | 型別檢查加上對比與字級檢查             |
| `npm run typecheck`      | 只做型別檢查                           |
| `npm run check:contrast` | 只做 WCAG AA 對比與最小字級檢查        |

## 資料存放

- 主檔：`data/momentum.json`，由開發伺服器的 `/api/data` 讀寫。
- 瀏覽器 localStorage 會同步存一份暫存；第一次啟動時若檔案是空的，會把瀏覽器裡的舊資料搬進檔案。伺服器沒開時，頁面右上角會顯示「僅存在瀏覽器」。
- 「回顧」頁可匯出／匯入 JSON；匯入會覆蓋目前所有紀錄，執行前會先確認。
- 紀錄是個人資料，已列入 `.gitignore`，不會被提交到 Git。專案的 GitHub 儲存庫若是公開的，提交上去就等於公開你的筆記與回顧。要備份請用匯出，或定期把 `data/` 資料夾複製到自己的私人位置。

資料結構（`src/types.ts` 的 `AppData`）：

```json
{
  "checks": { "2026-11-13": { "english": true } },
  "schedules": { "2026-11-13": [["09:00", "10:30", "自主專案深度工作 A", "deep"]] },
  "recover": { "2026-11-13": 1080 },
  "notes": { "2026-11-13": "..." },
  "reviews": { "2026-11-09": { "0": "..." } }
}
```

- `reviews` 的 key 是該週週一的日期。
- `schedules` 只存調整過的日子，內容是那一天完整的時間表；沒有紀錄的日子用 `src/config/schedule.ts` 的原定時間表。格式不正確的紀錄讀取時會被忽略。
- `confirmed` 是按過「保存當天時間表」、已經定稿的日期，定稿的日子不能再調整時間表。
- `recover` 有紀錄的日子就是勾了恢復模式，值是勾選當下這一天已經過的分鐘數（1080 就是 18:00）。結束時間晚於這個值的運動時段才取消，所以勾選前已完成的運動不會被劃掉。
- 舊版的 `modes` 會在讀取時轉換：選過恢復模式的日子轉成 `recover`（值為 0），存檔後 `modes` 就不再出現。

## 如何修改

- **改時間表**：編輯 `src/config/schedule.ts`。每個時段格式為 `[開始, 結束, 內容, 類型]`，星期 `0` 是週日。這是每天的原定時間表；只想臨時改某一天，用畫面上的「調整時間表」。
- **改習慣或每週目標**：編輯 `src/config/habits.ts` 的 `HABITS`。每週目標取最初計畫區間的下限，例如英文每週 5 到 6 天，目標設 5。`detail` 欄位預留給之後決定的教材、運動菜單等細項。
- **改回顧問題**：編輯 `REVIEW_QUESTIONS`。
- **改顏色**：編輯 `src/styles/_tokens.scss`，改完跑 `npm run check:contrast`。
- **改規則**：編輯 `docs/rules.md`。規則若影響程式（調整與恢復的說明、每週目標、回顧問題），要同步改 `habits.ts`。
- **記待辦**：還沒完成的工作寫在 `docs/plan.md`，每個項目底下用 checkbox 列細項，做完一項就打勾，整個區塊完成後刪掉。

## 設計與無障礙

走印刷品的路線，配色取「清醒專注」，刻意避開常見的模板外觀：靛藍漸層、圓角卡片、陰影、膠囊徽章、左側色條。目標是 WCAG 2.2 AA，新增或修改 UI、顏色、字體之後，先跑 `npm run check`。

- **配色**：底色是白色（深色模式是深灰色），文字是藍黑色的墨，整頁只有一個亮青色，專門標示「現在」與「今天」，螢光筆的黃是唯一的暖色，所以「專注」類的時段最先被看到。淺色模式的底色與內容面同為白色，物件的分界靠邊框。色票全部在 `src/styles/_tokens.scss`。
- **字型**：內文用系統的無襯線字體；標題、日期與大字用襯線體，優先 Noto Serif TC，找不到時退回其他系統襯線字體。全部是系統字型，不下載網路字型，所以不同電腦上的字形會略有差異。
- **形狀與標記**：方角，用粗細不同的橫線分段，沒有陰影。整頁只有「現在」區塊加框，像一張票，進度條像尺；現在的時段用青色框圈起來；時段類型用螢光筆底色輔助；「現在」「今天」「取消」是印章式的外框標記。
- **對比與字級**：一般文字至少 4.5:1（螢光筆底色上的文字也一樣），邊框、焦點框、進度條至少 3:1，任何文字不小於 14px，字級與間距一律用 rem。`check:contrast` 會編譯 SCSS，淺色與深色各檢查一遍，任何一組不合格就失敗；新增顏色配對時加進 `scripts/check-contrast.mjs` 的 `PAIRS`，字級門檻是 `MIN_FONT_PX`。
- **不只靠顏色**：現在的時段有青色外框與「現在」標記，已過的時段有底色與只給閱讀器的「已過」文字，達標有文字「達標」，今天有方塊或外框的形狀，選中的按鈕靠墨色實心與 `aria-pressed`。螢光筆底色只是輔助，時段類型本來就寫在文字裡。
- **鍵盤與閱讀器**：全部用原生元件，Tab 順序等於視覺順序；有跳過連結與地標，輸入欄位都有 label；換頁後焦點移到頁面標題，資料變動重繪後焦點回到原本的元件；「現在」的進度就地更新，換時段才重畫，不會頻繁打斷閱讀器。主要控制項至少 44px 高，其餘不小於 24px。
- **縮放與系統偏好**：寬度 320px 不出現橫向捲軸，文字放大 200%、調整行距與字距都不破版；跟隨淺色／深色、減少動態、提高對比。Windows 高對比模式下，選中、完成與目前時段改用系統色，螢光筆底線會關閉，避免變成蓋住文字的粗線。
