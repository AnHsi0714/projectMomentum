# 規則：作息、習慣與專案制度

這份文件是計畫的規則本身。還沒完成的工作記在 [plan.md](plan.md)，程式怎麼跑、怎麼改見 [README](../README.md)。

時段名稱的意思、命名規則與時間不夠時的取捨順序，在網頁的「名詞」頁，內容寫在 `src/config/terms.ts`。

**時間表不抄在這裡。** 每天的時段以 `src/config/schedule.ts` 為唯一來源，要改時間表就改那支檔案，免得兩邊對不上。

目前是 V1：先定整體架構，運動與自主專案的細項還沒決定，見 [plan.md](plan.md)。

## 目的

這套系統的目的不是讓每分鐘都有事情做，而是讓重要的事情穩定發生。

## 每天的定位

| 星期 | 主題                 | 重點                                                                 |
| ---- | -------------------- | -------------------------------------------------------------------- |
| 週一 | 長時間上課日         | 低負荷，不安排運動，也不安排自主專案深度工作，重點是維持生活節奏     |
| 週二 | 課業與自主專案日     | 不安排運動，保留一個完整的深度工作區塊                               |
| 週三 | 課業與英文日         | 以維持校內成績為主，不安排運動                                       |
| 週四 | 運動與自主專案日     | 運動日                                                               |
| 週五 | 自主專案與運動日     | 運動日                                                               |
| 週六 | 自主專案與能力培養日 | 運動日                                                               |
| 週日 | 課業整理與每週回顧日 | 恢復與規劃日                                                         |

## 固定作息規則

| 項目 | 規則                                            |
| ---- | ----------------------------------------------- |
| 起床 | 上課日依課表；週五至週日約 08:30                |
| 睡覺 | 每天 23:00                                      |
| 通勤 | 善用零碎時間，但不強迫學習                      |
| 洗澡 | 回家後處理，運動日運動後洗澡                    |
| 晚餐 | 時間浮動，不要求固定開始                        |
| 早餐 | 時間表不安排早餐，週五至週日併進 13:00 的早午餐 |

特別注意：18:40 到 19:20 不安排洗澡。

## 深度工作規則

1. 每個深度工作區塊以 60 到 90 分鐘為主。
2. 一次只處理一個主要任務。
3. 開始前先確認這個區塊要產出什麼。
4. 結束時記錄進度與下一步。
5. 不以工作時間長短作為唯一成果標準。
6. 被晚餐或突發事件中斷時，記錄進度後暫停，不必硬撐到時間結束。

網頁「今天」頁的「今日產出與進度」欄位，就是用來記第 3 與第 4 條。

## 休息規則

目前比較需要改善的不是休息時間太長，而是休息容易失去結束點，因此採用以下規則：

- 休息前先決定要休息多久。
- 看影片或使用手機時，設定結束鬧鐘。
- 休息時盡量離開原本的工作位置。
- 休息結束後先回到下一個預定任務，不再重新考慮要不要開始。
- 不把娛樂視為罪惡，也不因為休息超時就懲罰自己。

## 運動規則

| 星期 | 運動安排       |
| ---- | -------------- |
| 一   | 休息           |
| 二   | 休息           |
| 三   | 休息           |
| 四   | 運動           |
| 五   | 運動           |
| 六   | 運動           |
| 日   | 輕量活動或恢復 |

週日不是第四個高強度訓練日。若身體疲勞，可以完全休息。

## 突發事件處理規則

網頁「今天」頁的「今日調整」有兩個工具，平常照原定時間表執行，用得到時再開。

**調整時間表**：臨時有事、晚餐延遲或行程變動時：

- 保留當天最重要的一項任務。
- 其他任務縮短、交換順序或取消。
- 不延後睡眠來補進度。

網頁按「調整時間表」後，可以調整任務的先後、修改名稱與開始時間、新增與刪除任務。只填開始時間，每個任務延續到下一個任務開始，最後一個到 23:00 就寢。按「更新時間表」儲存後還能再調整，整天的任務都能改，包括已經結束的；按「保存當天時間表」會儲存並定稿，這一天之後不能再調整。過去的日子也不能調整。調整只套用在那一天，可以隨時還原成原定時間表。

**恢復模式**：身體不舒服、頭痛、腸胃不適或精神狀態差時，勾選「恢復模式」：

- 優先處理身體狀況。
- 取消運動及非急迫任務。
- 恢復後直接接回正常時間表。

網頁在恢復模式會把還沒完成的運動時段標示為取消，勾選前已完成的不受影響。非急迫的任務網頁不會自動判斷，用「調整時間表」自己縮短或刪除。

**最重要的一條：不補償原則。** 今天沒完成的任務，不代表明天要做兩倍。不要為了維持計畫而犧牲睡眠、休息或健康。

## 自主專案制度

自主專案是週二、週四、週五、週六的主要自主工作，最多兩個同時進行，而不是同時開很多個新目標。

**最多兩個專案**：同一時間最多兩個自主專案。兩個專案會平分深度工作時段，每個的進度大約慢一半，里程碑要設小一點。

執行時段：

- 週二：1 個深度工作區塊
- 週四：1 個深度工作區塊
- 週五：2 個深度工作區塊
- 週六：2 個深度工作區塊

每週日回顧：

- 確認本週完成進度。
- 檢查是否達成原定里程碑。
- 決定下週最重要的交付成果。

自主專案不只是寫程式，也可以是研究、產品設計、UX 實驗或完整作品。重點是最後要有可展示、可驗收的成果。

專案管理規則：

1. 同一時間最多兩個自主專案；一個深度工作時段只做其中一個，開始前先決定。
2. 專案需要有明確目標與完成條件。
3. 拆成階段，每階段有可驗收成果。
4. 每次工作前確認本次任務。
5. 每週日檢查進度，必要時調整下一週安排。
6. 已經有兩個專案時，完成一個才開下一個，不急著開新坑。
7. 課業做不完時，自主專案的時段可以改做課業，用「調整時間表」改名稱即可。課業有期限，優先處理。

## 英文學習制度

**完整的學習指令放在 NotebookLM，不抄在這裡。** 要改學習方式就改 NotebookLM 的指令，這裡只記會影響時間表與習慣追蹤的規則。

- 以 Input-based Learning 為主：透過影片、文章、訪談接觸新知識，不上制式文法課。
- 每週一個主題，素材可以是一份長素材、幾份短素材或混合。
- 每週總時數 4 到 4.5 小時，分成四個階段：

| 階段             | 每週時間     | 內容                                   |
| ---------------- | ------------ | -------------------------------------- |
| Input            | 90 到 120 分 | 閱讀或觀看素材，先抓主旨再看細節       |
| Concept Learning | 60 分        | 5 到 8 個單字片語、1 到 2 個文法句型   |
| Output           | 60 到 75 分  | 摘要、回答問題、表達看法等，形式要輪替 |
| Review           | 30 分        | 複習單字文法，記錄本週成果             |

- 每週日回顧時，把本週學習紀錄交給 NotebookLM，再產生下週規劃。
- 找素材用能上網搜尋的工具，確認網址存在後再加進 NotebookLM。NotebookLM 只根據來源回答，請它推薦網址容易出現不存在的連結。
- 當週沒做完不補課，也不壓縮下週時間，同樣適用不補償原則。

## 閱讀制度

Momentum 只負責追蹤閱讀，不安排讀什麼。

| 追蹤項目 | 記錄方式             |
| -------- | -------------------- |
| 本週閱讀 | 是否完成 2 小時      |
| 閱讀進度 | 書名、目前章節       |
| 閱讀反思 | 是否有值得記錄的想法 |

- 每天讀了就在「今天」頁打勾，每週目標 4 天，平均一次約 30 分鐘。
- 時數、書名章節與反思不另外做欄位，寫在每週回顧的閱讀問題裡。
- 沒讀滿 2 小時不補，同樣適用不補償原則。

## 每週習慣追蹤

第一版只追蹤這些，先不設定過多細項。實際使用時以每週紀錄為主，不必每天追求全部完成。

| 習慣               | 最初的計畫     | 程式的每週目標 |
| ------------------ | -------------- | -------------- |
| 固定時間起床與睡覺 | 每天           | 7              |
| 英文學習           | 每週 5 到 6 天 | 5              |
| 閱讀               | 每週 4 到 5 天 | 4              |
| 運動           | 每週 3 天      | 3                  |
| 自主專案           | 每週 4 天以上  | 4              |
| 課業整理           | 每週至少 2 次  | 2              |
| 每週回顧           | 週日           | 1              |

程式的目標取最初計畫區間的下限，做到就顯示「達標」。

## 對應到程式

- 時間表：`src/config/schedule.ts`。
- 習慣與每週目標、調整與恢復的說明、回顧問題：`src/config/habits.ts` 的 `HABITS`、`ADJUST_NOTE`、`RECOVER_NOTE`、`REVIEW_QUESTIONS`。
- 調整時間表與恢復模式的邏輯：`src/lib/schedule.ts` 與 `src/lib/blocks.ts`，調整後的內容存在 `data/momentum.json` 的 `schedules` 與 `recover`。
- 習慣的細項（教材、運動菜單等）決定後，填進 `HABITS` 的 `detail` 欄位。這個欄位目前只是預留，畫面還沒有顯示它。

規則若有改動，這份文件與上面這些檔案要一起改。
