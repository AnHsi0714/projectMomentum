# 規則：作息、習慣與專案制度

這份文件是計畫的規則本身，其他內容放在：

- 還沒完成的工作：[plan.md](plan.md)
- 專案介紹：[README](../README.md)
- 程式怎麼改：[development.md](development.md)
- 時段名稱的意思、命名規則與時間不夠時的取捨順序：網頁的「名詞」頁，內容寫在 `src/config/terms.ts`

**時間表不抄在這裡。**  
每天的時段以「設定」頁的每週範本（存在 `data/settings.json`）為唯一來源，要改時間表就在那裡改，免得兩邊對不上。  
設定檔還沒有範本時，用 `src/config/schedule.ts` 的預設值。

目前是 V1：先定整體架構，運動與自主專案的細項還沒決定，見 [plan.md](plan.md)。

## 目的

這套系統的目的不是讓每分鐘都有事情做，而是讓重要的事情穩定發生。

| ---- | -------------------- | -------------------------------------------------------------------- |
| 週一 | 長時間上課日         | 低負荷，不安排運動，也不安排深度工作，重點是維持生活節奏             |
| 週二 | 課業與自主專案日     | 不安排運動，保留一個完整的深度工作區塊                               |
| 週三 | 課業與英文日         | 以維持校內成績為主，不安排運動                                       |
| 週四 | 運動與自主專案日     | 運動日                                                               |
| 週五 | 自主專案與運動日     | 運動日                                                               |
| 週六 | 自主專案與能力培養日 | 運動日                                                               |
| 週日 | 課業與每週回顧日     | 恢復與規劃日                                                         |

## 固定作息規則

| 項目 | 規則                                            |
| ---- | ----------------------------------------------- |
| 起床 | 上課日依課表；週五至週日約 08:30                |
| 睡覺 | 每天 23:30                                      |
| 通勤 | 善用零碎時間，但不強迫學習                      |
| 洗澡 | 回家後處理，運動日運動後洗澡                    |
| 晚餐 | 時間浮動，不要求固定開始                        |

## 深度工作規則

1. 每個深度工作區塊以 60 到 90 分鐘為主。  
   內容不限自主專案，課業、閱讀文獻、學習 HCI 都可以。
2. 一次只處理一個主要任務。
3. 開始前先確認這個區塊要產出什麼。
4. 結束時記錄進度與下一步。
5. 不以工作時間長短作為唯一成果標準。
6. 被晚餐或突發事件中斷時，記錄進度後暫停，不必硬撐到時間結束。

時段名稱寫成「深度工作：A或B」，冒號後面依每天的主題寫這段做什麼，排前面的優先。  
第 3 與第 4 條記在網頁「今天」頁的「今日產出與進度」，也就是每日筆記。

## 休息規則

目前比較需要改善的不是休息時間太長，而是休息容易失去結束點，因此採用以下規則：

- 休息前先決定要休息多久。
- 看影片或使用手機時，設定結束鬧鐘。
- 休息時盡量離開原本的工作位置。
- 休息結束後先回到下一個預定任務，不再重新考慮要不要開始。
- 不把娛樂視為罪惡，也不因為休息超時就懲罰自己。

## 運動規則

| 星期 | 運動安排       |
| ---- | -------------- |
| 一   | 休息           |
| 二   | 休息           |
| 三   | 休息           |
| 四   | 運動           |
| 五   | 運動           |
| 六   | 運動           |
| 日   | 輕量活動或恢復 |

## 突發事件處理規則

網頁「今天」頁的「今日調整」有兩個工具：調整時間表與恢復模式。  
平常照原定時間表執行，用得到時再開。

### 調整時間表的原則

臨時有事、晚餐延遲或行程變動時：

- 保留當天最重要的一項任務。
- 其他任務縮短、交換順序或取消。
- 不延後睡眠來補進度。

### 時段的種類

- **固定**：上課、通勤、臨時行程、睡前準備、平日的起床。  
  照時鐘自動開始與結束，不用按，也不能拖動。結束時間到了就算完成。
- **任務**：深度工作、英文、運動、閱讀、規劃與回顧。  
  按「開始」才開始，按「結束」才結束。任務也可以在調整時切換成固定。
- **浮動事項**：吃飯、洗澡整理、浮動的起床。  
  長度大致固定，但不知道什麼時候開始，所以不排在時間表上，時間到了一樣要按「開始」。
- **空白**：任務之間沒排東西的時間，畫面上寫成休息，也就是自由時間與彈性時間。

起床每天各自設定時間、長度，以及是固定還是浮動事項。  
目前週一到週四是固定（起床後馬上要通勤），週五到週日是浮動事項。

浮動事項依序分成三個階段：起床、早午餐、洗澡與晚餐（洗澡和晚餐不分先後）。

- 後面階段的做過了，前面還沒做的就不再列出。
- 沒按起床就開始別的事，第一筆紀錄的時間就當成起床時間。

### 開始與結束

時間表是參考，不會因為晚開始而移動，實際做了什麼記在「現在」區塊。

- 任務按「開始」才開始。  
  「現在」區塊列出下一個任務：預定時間還沒結束、還沒開始的第一個，並寫出比預定晚了多久。
- 按了「結束」，之後到下一個任務開始之前都是休息。
- 沒按結束就開始下一個任務，前一個記到現在，等於前一個延長了。
- 浮動事項按「開始」時，正在做的任務先中斷。  
  浮動事項結束後，「現在」區塊會出現「繼續」，按了才接著做，不按就是休息。
- 任務做到一半要停下來，按「暫停」，和被浮動事項打斷一樣記成中斷。  
  之後「現在」區塊會出現「繼續」，還剩的長度照算。浮動事項不能暫停，只能結束。
- 按了結束又想再做（或按錯結束），「現在」區塊有「接著做」，從現在記新的一段，中間的休息不算。  
  只列最後結束的那個任務；預定長度已經用完，不再問還在不在做。
- 做 B 做到一半想回去把 A 做完，按「回到『A』」：B 先暫停，A 從現在接著做。  
  A 做完按結束，休息時再按「繼續『B』」回來。A 是 B 之前的那個任務，浮動事項不算。
- 休息時，所有被打斷或暫停、還沒做完的任務都列出「繼續」，最近停下來的排前面。
- 過了就寢時間，「現在」區塊不再列開始、繼續、接著做與浮動事項，沒做完的不延後睡眠來補。
- 固定時段開始時（例如睡前準備），正在進行的任務自動結束。
- 超過預定長度一半還沒按結束，「現在」區塊會問還在不在做。  
  可以回答還在做、在預定時間結束，或結束於現在。
- 預定時間過了還沒開始的任務記成「沒做」，不排到下一個，也不移到明天。  
  被浮動事項打斷的任務例外，可以按「繼續」。
- 忘了按開始或結束、按錯，或時間記錯，都在「調整時間表」裡直接改實際紀錄，見下面的調整時間表的操作。

這樣沒做完、晚開始都不用調整時間表。  
調整時間表用在計畫真的變了（例如臨時開會），或實際紀錄要修正的時候。

時間表以實際為準，計畫只是一開始的安排；平常的時間表照實際的情形排，計畫本身不改：

- 做過的照實際紀錄排，浮動事項也列進來。  
  左邊是實際的時間，右邊是計畫的時間，浮動事項右邊寫「浮動」。
- 被浮動事項打斷再繼續的任務分成兩列，中間是那個浮動事項。
- 進行中的任務照實際開始加上預定長度推算結束，後面的休息跟著往後推。  
  例如晚 2 分鐘開始，原本 19:30 結束，休息就從 19:32 開始。
- 過了時間沒做的任務留在計畫的位置，標「沒做」。
- 到了預定時間還沒按開始的任務標「還沒開始」。
- 還沒做的照計畫的時間排。
- 任務之間的休息也跟著時間走：過了的底色下沉，現在正在休息的框起來，標「現在」與還剩多久。

起床是浮動的日子起得晚，不用調整任何東西：按「起床」記下實際的起床時間，第一個任務晚一點按開始就好。  
「本週」頁會寫出實際的起床時間與目標，偷懶看得到，但不懲罰自己。

### 習慣達標

- 不能手動勾選。活動依類型對應習慣，同一個習慣當天有一項完成就算達標。怎樣算完成看活動的種類：
  - 任務：按了結束（不是被打斷）。
  - 固定時段：結束時間到了。恢復模式取消的不算。
  - 有目標時間的浮動事項（假日起床）：比目標晚 30 分鐘以內按開始。沒按起床就開始別的事，用第一筆紀錄的時間。
- 「今天」頁的「今日達標」列出今天已經開始或能判斷的項目，還沒開始的不列。  
  例如「英文學習 ✓」「深度工作 ×2　1/2」「固定時間起床與睡覺　09:10 起床，目標 08:30」。
- 完成一律打勾 ✓（報讀器念「完成」），時間表上的任務、今日達標與每週目標都一樣。
- 本週累積在「本週」頁。

### 調整時間表的操作

按「調整時間表」後，時間表改成撐滿版面的單欄，上方是橫向的時間條。

- **拖動**：按住任務左右拖是移動，拖右邊緣是改長度，一格 5 分鐘。
- **衝突**：任務可以拖過、蓋過別的任務，重疊時分成上下兩排。  
  時間條下面列出衝突，全部解開才能按「確認」。
- **對調**：先把一個任務拖到另一個上面，再把另一個拖回原位，中間的任務都不會動。
- **做過的照實際**：有實際紀錄的任務與浮動事項照實際的時間列出，被打斷再繼續的任務分成兩段。  
  拖動、改長度、刪除改的就是實際紀錄；沒做的照計畫列出，改的是計畫。
  - 進行中的先畫到預計結束（實際開始加上還剩的長度），已經超過就到下一個 5 分鐘。  
    結束拉到哪裡，確認後預計結束就在哪裡。
  - 被打斷的任務改名稱或類型，每一段一起改。
- **有做**：切換一列是做過還是計畫。
  - 忘了按開始：把任務拖到實際開始的時間，按「有做」。結束在現在之後的就是還在進行。
  - 忘了按結束：把做過的那一列拉到實際結束的時間。
  - 按錯了：按「有做」取消，留在原處當計畫；不要了就刪除。
  - 只有在現在之前開始的任務能記成有做；固定時段照時鐘走，不用記。
- **插入**：臨時有確定時間的事（例如開會），填開始時間（24 小時制）與長度。  
  放在那個時間，不推動原本的任務，重疊的話一樣列成衝突。
  - 整段都在現在之前的任務，當成忘了記的事，直接記成有做。
  - 忘了記吃飯、洗澡：項目選那個浮動事項，開始要在現在之前。
- **合併**：同一件事接在一起或重疊不算衝突，時間條下面列成「會合併」，確認時合成一段。
  - 做過的：同一個任務或浮動事項的紀錄，例如被打斷的兩段拖到接在一起。中斷的標記照後面那一段。
  - 計畫：名稱、類型與是否固定都相同的任務。做過的和計畫不合併。
- **衝突**：做過的彼此重疊一定是衝突，同一段時間不能做兩件事。  
  牽涉到計畫或固定時段的重疊只看現在之後的部分；現在之前的計畫只是參考，例如沒做的任務或通勤和做過的事疊在一起，不用為了它去改。
- **單一任務**：可以修改名稱與類型、切換有做與固定、移到暫待區或刪除。  
  做過的不能設成固定，也不能移到暫待區。
- **狀態**：做過而且還沒結束的標「進行中」，浮動事項標「浮動」；計畫過了時間沒做的標「沒做」，固定時段結束了標「已過」。
- **暫待區**：今天先不排、還沒決定要不要做的任務，可以排回時間表或刪除。
- **限制**：最後一個任務最晚到 23:30 就寢。只要不是舊版定稿的日子都能調整，包括過去的日子，用來修正實際紀錄。
- **儲存**：確認後實際紀錄整份換掉，習慣達標跟著重新算：同一個習慣當天還有任務做完就留著，沒有就取消。
  - 做過的任務在計畫裡保留原本的時間當參考；還在進行的，計畫長度改成做過的加上這一段。
  - 確認後還能再調整，整天的任務都能改，包括已經結束的。
- **還原**：計畫還原成原定時間表；做過的回到開始調整前的樣子，不會因為還原而消失。

### 恢復模式

身體不舒服、頭痛、腸胃不適或精神狀態差時，勾選「恢復模式」：

- 優先處理身體狀況。
- 取消運動及非急迫任務。
- 恢復後直接接回正常時間表。

網頁會把還沒完成的運動時段標示為取消，勾選前已完成的不受影響。  
因為只會取消運動，那天還有沒結束的運動時才顯示這個開關；已經啟用的會一直顯示，才能關掉。  
非急迫的任務網頁不會自動判斷，用「調整時間表」自己縮短或刪除。

### 不補償原則

**這是最重要的一條。**  
今天沒完成的任務，不代表明天要做兩倍。  
不要為了維持計畫而犧牲睡眠、休息或健康。

## 自主專案制度

自主專案主要在週二、週四、週五、週六的深度工作時段進行。  
同一時間最多兩個，不同時開很多個新目標。  
兩個專案會平分深度工作時段，每個的進度大約慢一半，里程碑要設小一點。

執行時段：

- 週二：1 個深度工作區塊
- 週四：1 個深度工作區塊
- 週五：2 個深度工作區塊
- 週六：2 個深度工作區塊

每週日回顧：

- 確認本週完成進度。
- 檢查是否達成原定里程碑。
- 決定下週最重要的交付成果。

自主專案不只是寫程式，也可以是研究、產品設計、UX 實驗或完整作品。  
重點是最後要有可展示、可驗收的成果。

專案管理規則：

1. 同一時間最多兩個自主專案；一個深度工作時段只做其中一個，開始前先決定。
2. 專案需要有明確目標與完成條件。
3. 拆成階段，每階段有可驗收成果。
4. 每次工作前確認本次任務。
5. 每週日檢查進度，必要時調整下一週安排。
6. 已經有兩個專案時，完成一個才開下一個，不急著開新坑。
7. 深度工作時段不一定做自主專案，名稱冒號後面寫了這段預設做什麼。  
   課業做不完時優先課業，臨時要換就用「調整時間表」。

## 英文學習制度

**完整的學習指令放在 NotebookLM，不抄在這裡。**  
要改學習方式就改 NotebookLM 的指令，這裡只記會影響時間表與習慣追蹤的規則。

- 以 Input-based Learning 為主：透過影片、文章、訪談接觸新知識，不上制式文法課。
- 每週一個主題，素材可以是一份長素材、幾份短素材或混合。
- 每週總時數 4 到 4.5 小時，分成四個階段：

| 階段             | 每週時間     | 內容                                   |
| ---------------- | ------------ | -------------------------------------- |
| Input            | 90 到 120 分 | 閱讀或觀看素材，先抓主旨再看細節       |
| Concept Learning | 60 分        | 5 到 8 個單字片語、1 到 2 個文法句型   |
| Output           | 60 到 75 分  | 摘要、回答問題、表達看法等，形式要輪替 |
| Review           | 30 分        | 複習單字文法，記錄本週成果             |

- 每週日回顧時，把本週學習紀錄交給 NotebookLM，再產生下週規劃。
- 找素材用能上網搜尋的工具，確認網址存在後再加進 NotebookLM。  
  NotebookLM 只根據來源回答，請它推薦網址容易出現不存在的連結。
- 當週沒做完不補課，也不壓縮下週時間，同樣適用不補償原則。

## 閱讀制度

Momentum 只負責追蹤閱讀，不安排讀什麼。

| 追蹤項目 | 記錄方式             |
| -------- | -------------------- |
| 本週閱讀 | 是否完成 2 小時      |
| 閱讀進度 | 書名、目前章節       |
| 閱讀反思 | 是否有值得記錄的想法 |

- 每天讀了就在「今天」頁打勾，每週目標 4 天，平均一次約 30 分鐘。
- 時數、書名章節與反思不另外做欄位，寫在每週回顧的閱讀問題裡。
- 沒讀滿 2 小時不補，同樣適用不補償原則。

## 每週習慣追蹤

第一版只追蹤這些，先不設定過多細項。  
實際使用時以每週紀錄為主，不必每天追求全部完成。

| 習慣               | 最初的計畫     | 程式的每週目標 |
| ------------------ | -------------- | -------------- |
| 固定時間起床與睡覺 | 每天           | 7              |
| 英文學習           | 每週 5 到 6 天 | 5              |
| 閱讀               | 每週 4 到 5 天 | 4              |
| 運動               | 每週 3 天      | 3              |
| 深度工作           | 每週 4 天以上  | 4              |
| 每週回顧           | 週日           | 1              |

程式的目標取最初計畫區間的下限，算的是天數：同一天做好幾次只算一天，做到就打勾 ✓。  
達標的天數都依實際紀錄自動計算，起床依起床時間判斷。  
「本週」頁在名稱下面補上這週完成的次數與實際做了多久，起床不算時數。

## 對應到程式

- 時間表：「設定」頁，存在 `data/settings.json` 的 `template`，預設值在 `src/config/schedule.ts` 的 `DEFAULT_TEMPLATE`。
- 習慣與每週目標、調整與恢復的說明、回顧問題：`src/config/habits.ts`。  
  分別是 `HABITS`、`ADJUST_NOTE`、`RECOVER_NOTE`、`REVIEW_QUESTIONS`。
- 任務對應哪個習慣：`src/config/habits.ts` 的 `TYPE_HABIT`，依類型對應。
- 調整時間表與恢復模式的邏輯：`src/lib/schedule.ts`、`src/lib/blocks.ts` 與 `src/lib/draft.ts`。
- 哪些活動是浮動事項：每週範本裡 `mode` 是 `float` 的活動。
- 開始、結束與自動勾選習慣：`src/lib/log.ts`。
- 調整時間表時改實際紀錄、「有做」與衝突的判斷：`src/lib/draft.ts`。
- 資料：`data/momentum.json` 的 `schedules`、`pending`、`log` 與 `recover`。
- 習慣的細項（教材、運動菜單等）決定後，填進 `HABITS` 的 `detail` 欄位。  
  這個欄位目前只是預留，畫面還沒有顯示它。

規則若有改動，這份文件與上面這些檔案要一起改。
