# 開發說明

給要修改程式的人。  
專案介紹與使用方式見 [README](../README.md)，作息規則見 [rules.md](rules.md)。

## 指令

| 指令                     | 說明                                   |
| ------------------------ | -------------------------------------- |
| `npm run dev`            | 開發伺服器，含存檔功能                 |
| `npm run build`          | 先跑 `check`，通過後建置到 `dist/`     |
| `npm run preview`        | 預覽建置結果（同樣含存檔功能）         |
| `npm run check`          | 型別檢查加上對比與字級檢查             |
| `npm run typecheck`      | 只做型別檢查                           |
| `npm run check:contrast` | 只做 WCAG AA 對比與最小字級檢查        |

## 用指定時間檢查畫面

想在別的時間檢查「現在」區塊與進度尺，在網址的 `#` 前面加上 `?now=21:15`。  
例如 `http://localhost:5173/?now=21:15#/today`。  
日期仍是今天，時間會停在那一刻；正式建置不理會這個參數。

## 資料存放

- 主檔：`data/momentum.json`，由開發伺服器的 `/api/data` 讀寫。
- 瀏覽器 localStorage 會同步存一份暫存。
  - 第一次啟動時若檔案是空的，會把瀏覽器裡的舊資料搬進檔案。
  - 伺服器沒開時，頁面右上角會顯示「僅存在瀏覽器」。
- 「回顧」頁可匯出／匯入 JSON；匯入會覆蓋目前所有紀錄，執行前會先確認。
- 紀錄是個人資料，已列入 `.gitignore`，不會被提交到 Git。
  - 儲存庫若是公開的，提交上去就等於公開你的筆記與回顧。
  - 要備份請用匯出，或定期把 `data/` 資料夾複製到自己的私人位置。

資料結構（`src/types.ts` 的 `AppData`）：

```json
{
  "template": { "1": [{ "id": "wake", "label": "起床、盥洗、準備", "type": "wake", "mode": "clock", "start": "07:20", "minutes": 40 }, { "id": "dinner", "label": "晚餐", "type": "meal", "mode": "float", "minutes": 70, "stage": 2 }] },
  "checks": { "2026-11-13": { "english": true } },
  "schedules": { "2026-11-13": [{ "id": "p1", "start": "09:00", "end": "10:30", "label": "深度工作：專案", "type": "deep" }, { "id": "tm3k2a1b", "start": "14:00", "end": "15:00", "label": "小組會議", "type": "event" }] },
  "pending": { "2026-11-13": [{ "id": "p5", "start": "16:00", "end": "16:40", "label": "運動", "type": "exercise" }] },
  "log": { "2026-11-13": [{ "ref": "p1", "label": "深度工作：專案", "type": "deep", "start": "09:20", "end": "10:05", "cut": true }, { "ref": "brunch", "label": "早午餐", "type": "meal", "start": "10:05", "end": "10:50", "float": true }] },
  "confirmed": { "2026-11-13": true },
  "recover": { "2026-11-13": 1080 },
  "notes": { "2026-11-13": "..." },
  "reviews": { "2026-11-09": { "0": "..." } }
}
```

- `template` 是每週範本，key 是星期（`0` 是週日），值是那一天的活動（`types.ts` 的 `Activity`）。
  - 資料裡沒有時用 `src/config/schedule.ts` 的 `DEFAULT_TEMPLATE`，存檔後就寫進資料檔。  
    之後改時間表要改資料檔的 `template`，改 `DEFAULT_TEMPLATE` 不會影響已經有範本的資料。
  - `mode`：`clock` 固定（照時鐘走）、`press` 任務（按了才算）、`float` 浮動事項。
  - `clock`、`press` 一定有 `start`；`float` 的 `start` 可省略，起床寫了就是目標時間。`stage` 只有 `float` 用。
  - `id` 寫進資料後不再變，實際紀錄的 `ref` 靠它對應，同一天裡不能重複。
  - 某一天格式不對（缺欄位、id 重複、排到就寢之後），那一天整天改用預設範本。
  - 起床是類型 `wake` 的活動，固定的到了結束時間就算達標，浮動的按「起床」和 `start` 比。
- `reviews` 的 key 是該週週一的日期。
- `schedules` 只存調整過的日子，內容是那一天完整的時間表，只有固定與任務。
  - 沒有紀錄的日子用 `template` 產生的原定時間表。
  - 任務之間可以有空白（自由時間、彈性時間）。
  - 可以重疊：做過的任務保留原本的計畫時間當參考，可能和後來排的任務疊在一起。  
    不能重疊的是實際紀錄與現在之後的安排，調整時由 `draft.ts` 的 `draftConflicts` 檢查。
  - 名稱、類型與是否固定都相同而且接在一起或重疊的任務，儲存時會合併（`blocks.ts` 的 `mergeTouching`）。  
    實際紀錄也一樣，同一個任務或浮動事項接在一起或重疊的合成一段（`draft.ts` 的 `sameItem`）。
  - 讀取舊紀錄時：浮動事項、休息、自由時間與彈性時間會拿掉，沒合併的相同任務顯示時當成一個，格式不正確的會被忽略。
- 每個時段是物件：`id`、`start`、`end`、`label`、`type`、`mode`。
  - `mode` 是 `clock`（固定時段）或 `press`（任務）。
  - 舊版沒有 `mode`，讀取時用 `locked` 換算；`locked` 也沒寫的，上課、通勤、臨時行程是 `clock`。
  - 原定時間表的 id 照抄範本活動的 id，插入的任務是亂數。  
    舊版的 id 是 `p` 加上位置（`p0`、`p1`），只留在已經調整過的日子裡。
  - 舊版的陣列格式讀取時會自動轉換；舊版類型是 `prep`、名稱有「起床」的，轉成 `wake`。
- `checks` 是每天達標的習慣，任務按結束時自動寫入。
  - 確認調整時重新算：牽涉到的習慣，當天沒有任務做完就拿掉。
  - 固定時段與有目標時間的浮動事項不寫進這裡，每次依時間計算（`lib/log.ts` 的 `habitItems`）。
  - 舊資料裡手動勾的值還留著（起床的 `sleep` 讀取時拿掉），但畫面不再提供勾選。
- `log` 是實際紀錄：按開始、結束記下的每一段，`ref` 是任務或浮動事項的 id。
  - 沒有 `end` 的是正在進行的。
  - `cut` 是被浮動事項打斷，`float` 是浮動事項，`long` 是超過預定長度後回答過還在做。
- `pending` 是暫待區：調整時間表時拿出時間表、還沒決定要不要做的任務。  
  時間是拿出前的時間。
- `confirmed` 是舊版按過「保存當天時間表」、已經定稿的日期，這些日子不能再調整時間表。  
  現在只剩「確認」，不會再產生新的定稿紀錄。
- `recover` 有紀錄的日子就是勾了恢復模式，值是勾選當下這一天已經過的分鐘數（1080 就是 18:00）。  
  結束時間晚於這個值的運動時段才取消，所以勾選前已完成的運動不會被劃掉。
- 舊版的 `modes` 會在讀取時轉換：選過恢復模式的日子轉成 `recover`（值為 0），存檔後 `modes` 就不再出現。

## 如何修改

- **改畫面**：畫面的區塊在 `src/components/`，`src/views/` 只負責組合。
  - 元件是一般函式，傳入資料、回傳 lit-html 的 `html` 模板。
  - 不用 `LitElement`：Shadow DOM 會切斷 `aria-describedby`、`<label for>` 這類跨元件的 id 關聯，全域樣式也進不去。
  - 文字直接放進 `${}` 就會自動跳脫，不要自己組 HTML 字串。
  - 表單欄位的值用 `.value=${live(...)}`、勾選用 `.checked=${live(...)}`，換天或換週時才會更新。
  - 事件不綁在模板上，統一由 `main.ts` 在 `#main` 上委派處理。

- **改時間表**：編輯 `data/momentum.json` 的 `template`（格式見上面的資料結構），改完重新整理頁面。
  - 目前還沒有設定畫面，之後會改成在畫面上編輯。
  - `src/config/schedule.ts` 的 `DEFAULT_TEMPLATE` 只在資料檔沒有範本時使用。
  - 自由時間與彈性時間不用寫，活動之間留空就是空白。
  - 就寢時間是 `schedule.ts` 的 `SLEEP_TIME`，時段名稱照 `src/config/terms.ts` 的用詞。
  - 只想臨時改某一天，用畫面上的「調整時間表」。
- **改任務對應的習慣**：編輯 `src/config/habits.ts` 的 `TYPE_HABIT`，依類型對應。
- **改習慣或每週目標**：編輯 `src/config/habits.ts` 的 `HABITS`。  
  `detail` 欄位是習慣的細項說明，目前畫面還沒有顯示。
- **改回顧問題**：編輯 `REVIEW_QUESTIONS`。
- **改名詞或取捨順序**：編輯 `src/config/terms.ts`。
- **改顏色**：編輯 `src/styles/_tokens.scss`，改完跑 `npm run check:contrast`。
- **改規則**：編輯 `docs/rules.md`。規則若影響程式要同步改：
  - 每週目標、調整與恢復的說明、回顧問題：`habits.ts`
  - 就寢時間：`schedule.ts` 的 `SLEEP_TIME`
  - 名詞與取捨順序：`terms.ts`
- **記待辦**：還沒完成的工作寫在 `docs/plan.md`，每個項目底下用 checkbox 列細項。  
  做完一項就打勾，整個區塊完成後刪掉。

## 設計與無障礙

走印刷品的路線，配色取「清醒專注」。  
刻意避開常見的模板外觀：靛藍漸層、圓角卡片、陰影、膠囊徽章、左側色條。  
目標是 WCAG 2.2 AA，新增或修改 UI、顏色、字體之後，先跑 `npm run check`。

- **配色**：色票全部在 `src/styles/_tokens.scss`。
  - 底色是白色（深色模式是深灰色），文字是藍黑色的墨。
  - 整頁只有一個亮青色，專門標示「現在」與「今天」。
  - 螢光筆的黃是唯一的暖色，所以「專注」類的時段最先被看到。
  - 淺色模式的底色與內容面同為白色，物件的分界靠邊框。
- **字型**：全部是系統字型，不下載網路字型，所以不同電腦上的字形會略有差異。
  - 內文用無襯線字體。
  - 標題、日期與大字用襯線體，優先 Noto Serif TC，找不到時退回其他襯線字體。
- **形狀與標記**：方角，用粗細不同的橫線分段，沒有陰影。
  - 整頁只有「現在」區塊加框，像一張票。
  - 進度條像尺，刻度對齊時鐘，間隔依時段長度變化（`views/today.ts` 的 `tickStep`）。  
    整點最長最粗、半點次之，尺下方寫著「每格幾分」。
  - 現在的時段用青色框圈起來，時段類型用螢光筆底色輔助。
  - 「現在」「今天」「取消」是印章式的外框標記。
- **對比與字級**：
  - 一般文字至少 4.5:1（螢光筆底色上的文字也一樣），邊框、焦點框、進度條至少 3:1。
  - 任何文字不小於 14px，字級與間距一律用 rem。
  - `check:contrast` 會編譯 SCSS，淺色與深色各檢查一遍，任何一組不合格就失敗。
  - 新增顏色配對時加進 `scripts/check-contrast.mjs` 的 `PAIRS`，字級門檻是 `MIN_FONT_PX`。
- **不只靠顏色**：螢光筆底色只是輔助，時段類型本來就寫在文字裡。
  - 現在的時段有青色外框與「現在」標記。
  - 已過的時段有底色，任務另外有 ✓、「沒做」這類狀態標記，沒有標記的固定時段補上只給閱讀器的「已過」。
  - 達標有文字「達標」，今天有方塊或外框的形狀。
  - 選中的按鈕靠墨色實心與 `aria-pressed`。
- **鍵盤與閱讀器**：
  - 全部用原生元件，Tab 順序等於視覺順序。
  - 有跳過連結與地標，輸入欄位都有 label。
  - 換頁後焦點移到頁面標題。
  - 重畫由 lit-html 處理，只改動有變化的地方，所以焦點不會跑掉，每分鐘更新「現在」也不會打斷閱讀器。
  - 主要控制項至少 44px 高，其餘不小於 24px。
- **縮放與系統偏好**：
  - 寬度 320px 不出現橫向捲軸，文字放大 200%、調整行距與字距都不破版。
  - 跟隨淺色／深色、減少動態、提高對比。
  - Windows 高對比模式下，選中、完成與目前時段改用系統色。  
    螢光筆底線會關閉，避免變成蓋住文字的粗線。
